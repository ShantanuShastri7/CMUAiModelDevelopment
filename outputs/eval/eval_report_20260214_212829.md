### Query 4: What is 'Self-RAG' and how does it work?
**Latency:** 0.57s
**Answer:**
Self-RAG is a retrieval-augmented generation model that determines if augmenting the continued generation with retrieved passages would be helpful, given an input prompt and preceding generations. It works by first outputting a retrieval token that calls a retriever model on demand (Step 1), then concurrently processing multiple retrieved passages to evaluate their relevance and generate corresponding task outputs (Step 2), and finally generating critique tokens to criticize its own output and choose the best one in terms of factuality and overall quality (Step 3) (Source: 2310.11511v1, Chunk: 2310.11511v1_chunk_4).

### Query 8: What is the difference between sparse and dense retrieval?
**Latency:** 0.63s
**Answer:**
The main difference between sparse and dense retrieval is their performance in terms of indexing and querying. Dense vector indexing has rapid indexing capability but is offset by relatively sluggish querying performance, whereas sparse vector indexing has a slower indexing process but offers expeditious querying advantages. Additionally, there is a stark contrast in storage requirements, with sparse vector indexing requiring significantly less storage space compared to dense vector indexing. For example, the sparse vector index of the HotPotQA corpus occupied 10.5GB, whereas the dense vector equivalent required 50GB (Source: 2404.07220v2, Chunk: 2404.07220v2_chunk_25).
